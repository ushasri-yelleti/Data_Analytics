** Client server architecture:-- (3 components)
1. client:-- The role of the client is to snd req to the server nd to get response frm the server.
2. server:-- It is a software to take requests frm the clients. If the req is valid, it will generate some response nd we can handover tht response to client. If the client req is not valid, it will raise some error status codes.
3. protocol:-- The protocol consists a set of rules to be followed while sending req frm client to server.

----CLAUSES----

In MYSQL clauses r used to control how data is filtered, grouped, sorted or modified in sql queries. They make sql statements more useful nd powerful.

----> WHERE CLAUSE:= Filters records based on specified conditions. where clause can be used as comparision, logical operators,etc
syntax;  select column1,column2....from table where condition;

----> GROUPBY CLAUSE:= Its used to group rows having the same values in one or more columns. It is commonly used by the aggregate functions such as min(),max(),sum(),count(),avg().
syntax; select columnname,aggregate_function(columnname) from tablename group by columnname;

----> HAVING CLAUSE:= Its used to filter grouped records after groupby clause. It is similar to where, but it works on gruped instead of individual rows
syntax:-- select columnname,aggregate_function(columname) from tablename group by columname having condition;

----> ORDERBY CLAUSE:= Its used to sort the result set in asecending/descending order
syntax: select columname from tablename order by columname;

****QUERIES AND SUB QUERIES****

SUBQUERY-- It is a query inside another query. It is written inside paranthesis() and its result is used by the outer query. It is also called as inner query, nested query nd inner select.
PURPOSE OF SUBQUERY:--
1. To break down complex prblms into smaller
2. To use the result of one query as input to another
3. To avoid multiple steps(write in a single query instead of temp tables).
General Syntax:--
select column-list from table where column operator(select column from table where condition);

Types of Sub queries:
1. single row sub query
2. multi row
3. nested
4. corelated
5. exists/non-exists

1. SINGLE ROW SUBQUERY:-- They return exactly one row nd column. They use comparision operators like =,>,>=,<,<=,!=
CHARACHTERISTICS:--
1. Returns only 1 value
2. Can use single value comparision operators
3. if subquery returns no rows or multiple rows it causes an error
SYNTAX:--
select columns from table where column operator(select column from table where condition);


2. Multi row:-- (a) multi-row subquery IN:-- It returns more than one row. The in operator is used when we want to compare a value with multiple values returned by the subquery.
CHARACHTERISTICS:--
Returns multiple rows
Use the IN Operator
checks whether a value exists in the list returned by the subquery.
equivalent to multiple OR conditions
most commonly used for matching values
SYNTAX:--
select column from a table where column IN(select column from table where condition);

(b) multi-row subquery(any/some):-- returns multiple rows when using ANY or SOME, the condition is true if it matches atleast one value returned by the subquery
CHARACHTERISTICS:--
Returns multiple values
ANY and SOME are interchangeable
condition is true if any of the values satisfy the condition
often used with IN, >ANY, >ANY,>=ANY...etc
SYNTAX:--
select column from table where column operator any/some(select column from table where condition);

(c) multi-row subquery all:-- the all operator means the condition must be true for all values returned by the subquery result
CHARACHTERISTICS:--
Conditions must be true for all values in the subquery result
often used with >all,<all,>=all,<=all
>all means greater than the maximum value
SYNTAX:--
select column from table where column operator all(select column from table where condition);

3. Nested:-- They r subqueries within subqueries nd can be of multiple levels deep nd are executed from innermost to the outermost
CHARACHTERISTICS:--
Multiple levels of nesting
inner queries execute first
can combine different types of subqueries
useful for complex condition
SYNTAX:--
select column-list from table where column=(select column from table where column=(select column from table where condition));


4. Corelated:-- They refer columns from outer queries unlike regular subqueries tht execute once. They execute once per each row processed by the outer query
Charachteristics:--
Reference col frm outer query
executes multiple times(once per outer row)
cannot be executed independently
often used with EXISTS/NOT EXISTS
generally slower than non corelated subqueries
Syntax:--
select column from table1 outer_alias where condition(select column from table2 inner_alias where inner_alias.column=outer_alias.column);


5.exists/non-exists:-- Exists is used to test whether a subquery returns any rows. It returns true if the subquery returns atleast one row. False otherwise
Non-exists returns true if the subquery returns no rows
CHARACHTERISTICS:--
Returns TRUE/False(Boolean result)
more efficient than IN for large datasets
often used with corelated subqueries
stops execution as soon as first match is found
select clauses in exists doesn't matter(often use select 1)
SYNTAX:--
select columns from table1 where exists(select1 from table2 where condition);

SYNTAX:--
select columns from table1 where not exists(select1 from table2 where condition);

****VIEWS****
A view is a virtual table created frm the result of select query. It doesn't normally stores the actual data separately, instead, it stores the sql query whenever u access the view, MySQL retrieves the data frm the underlying tables

why do we need views?
* simplify complex queries
* reuse query logic
* data security
* simplified reporting
Advantages of views:--
* security
* simplicity
* reusability
* 

diff btw table/view:--
 
TABLE                                                                                                                     VIEW

physically stores data                                                                                            virtual table based on query
can store records directly                                                                                        doesn't store separate records
create using create table                                                                                            create using create view
contains all table data                                                                                            can show selected rows/columns
used fr permanent data storage                                                                                        mainly used fr abstraction, security nd reusable queries



SYNTAX:-- ( create view)
create view view_name as select column from table where condition;
(altering view):--
alter view view_name as select new_columns from new_tables where new_conditions;
(drop a view):--
drop view view_name;

***STORED PROCEDURE***
It is a named, precompiled collection of one or more sql statements tht is stored inside the database nd can be executed called whenever required. Instead of sending long block of sql frm an application every time, the application simply calls the procedure by name.

Uses of stored procedure:--
1. performance
2. reusability
3. security
4. reduce network traffic
5. maintainability
6. consistency

***TRIGGERS***
It is a spcl type of stored program, that automatically executes (fires) in response to the specific event. Insert, Update, Delete occurring on a specified table, unlike a stored procedure. A trigger is never called directly

SYNTAX:--
DELIMITER//
CREATE TRIGGER trigger_name
{BEFORE|AFTER}{INSERT|UPDATE|DELETE}
ON table_name
FOR EACH ROW
begin 
    ----trigger logic
    --- use new column name for inserted/updated values
    --- use OLD.column_name for delete/previous values
END//
DELIMITE;
